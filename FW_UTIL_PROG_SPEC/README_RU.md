# Спецификация графической утилиты прошивки

## Кратко

Нужно создать графическую утилиту для прошивки Ethernet-модуля на STM32F407.
Утилита должна использовать существующий Modbus TCP OTA-процесс из
`tools/fw_update.mjs` и заменить консольный сценарий удобным интерфейсом для
оператора.

## Цели

- Читать статус бутлоадера
- Выбирать файл прошивки `.bin`
- Загружать прошивку по Modbus TCP
- Показывать прогресс и ошибки
- Поддерживать `abort` и `reboot`

## Что не входит в задачу

- Изменение протокола бутлоадера
- Замена текущего OTA-формата
- Добавление нового транспорта прошивки

## Функциональные требования

### Подключение

- Подключение по IP-адресу и TCP-порту
- Использование того же набора регистров и команд, что и в `fw_update.mjs`
- Выбор MAC через PDP (UDP/20556); при нескольких BL нужен явный выбор.
  Наблюдаемый конфликт IP — ошибка.
- Перед изменяющими командами BL читать MAC через то же TCP-соединение.
  Повторять после reconnect и SET_NET; одного bootloader magic недостаточно.
- Защищённые записи требуют BL 1.8+. Чтение статуса старых BL сохраняется,
  скрытого fallback при записи нет. Политика одинакова в Node и Qt.
- Возможность повторить подключение при ошибке

### Просмотр статуса

Показывать:

- состояние бутлоадера
- последнюю ошибку
- признак валидности приложения
- версию приложения
- product ID
- hardware revision
- количество полученных блоков / общее число блоков
- размер образа
- CRC32 образа
- статус команды
- признак валидного staging
- выбранный MAC и проверенную идентификацию подключённого устройства

### Прошивка

- Выбор локального файла `.bin`
- Расчёт и отображение размера образа и CRC32
- Отправка `BEGIN_UPDATE`
- Передача блоков с отображением прогресса
- Отправка `FINALIZE_UPDATE`
- Отправка `INSTALL_UPDATE`
- Понятный вывод результата и ошибок

До BEGIN проверить 28-байтный заголовок на смещении `0x200`: product ID совпадает
точно, `(header_hw >> 8) == (board_hw >> 16)`. HW платы — 24 бита, HW образа/OTA —
16 бит. FW version — `(major<<8)|minor`, берётся из образа. Неверный заголовок
отклоняется без подстановки дефолтной идентификации.

Размер блока кратен четырём и не превышает 240; число блоков равно
`ceil(image_size/block_size)`. Один FC16 с `0x0100` содержит индекс(2 регистра),
длину(1) и `ceil(length/2)` регистров данных. Последний блок — ровно остаток.
Идентичный повтор идемпотентен, изменённый отклоняется. BL проверяет read-back
Flash, а при FINALIZE — все биты bitmap и CRC ровно `image_size` байт.

FINALIZE сохраняет проверенный образ и ждёт INSTALL, в том числе после reset.
После сохранённого начала INSTALL reset перезапускает erase/copy с проверенного
staging. После reset во время приёма клиенты выполняют BEGIN и полную передачу.
ABORT недоступен во время установки и не восстанавливает стёртое приложение.
Modbus exception 6 означает занятость. Timeout/разрыв TCP не доказывает успех:
нужны BL OK либо приложение выбранного MAC с ожидаемыми product/version.

У BL один TCP-клиент. Новое соединение не вытесняет активного; idle timeout
30 с, незавершённого ADU 5 с, keepalive включён. Reconnect сам не отменяет OTA.
Таймаут запроса при Flash-операциях — 15 с. PDP SET_NET/REBOOT требуют точный
ненулевой MAC и запрещены во время установки; IDENTIFY остаётся широковещательным.

Актуальные IR (32-битные значения старшим словом вперёд): HW `0x000A..0x000B`,
ошибка `0x000C`, число блоков `0x000D..0x000E`, принято `0x000F..0x0010`,
размер `0x0011..0x0012`, CRC `0x0013..0x0014`, статус команды `0x0015`,
staging valid `0x0016`, app product ID `0x0017..0x0018`, MAC `0x0019..0x001B`.
MAC `02:00:12:34:56:78` передаётся как `0200 1234 5678`.
Полная авторитетная карта — комментарий `fw_update_proto.h`.

### Команды управления

- `Status`
- `Abort`
- `Reboot`
- `Select firmware`
- `Flash`

## Требования к интерфейсу

- Одно окно
- Поля IP-адреса, порта и выбранного MAC
- Кнопка выбора файла прошивки
- Индикатор прогресса передачи
- Окно логов
- Панель статуса бутлоадера

## Обработка ошибок

- Показ сетевых ошибок
- Перевод кодов ошибок бутлоадера в человекочитаемый вид
- Отсутствие зависания интерфейса во время прошивки
- Сохранение логов текущей сессии

## Критерии приёмки

- Оператор может читать статус бутлоадера без консоли
- Оператор может успешно прошить корректный `.bin`
- Утилита показывает прогресс передачи
- Утилита корректно сообщает об ошибке CRC и обрыве передачи
- Утилита отменяет приём и отклоняет отмену во время установки
- Неверный MAC, несколько BL без выбора и конфликт IP не запускают обновление
- Проверяются повторы, пропуски, неверные длины/индексы и последний неполный блок
- Потеря соединения не превращается в ложное сообщение об успехе
- Host-тесты дополняют реальные OTA и power-cut испытания, но не заменяют их

## Основа реализации

Графическая утилита должна быть основана на логике:

- `tools/fw_update.mjs`
- текущей карте регистров бутлоадера
- протестированном сценарии warm reset между app и bootloader
